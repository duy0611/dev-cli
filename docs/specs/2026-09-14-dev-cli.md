# Agent Dev CLI

A CLI to manage devcontainers with support for running Agentic Coding in the devcontainers (aka. sandbox).

It composes of 3 main components: CLI + UI + Engine
- CLI: the main `dev` cli written in go
- UI: can be a desktop app / browser webapp (no need to decide now - at this stage, let defer this feature to later implementation)
- DB: if running in local env, use sqlite. if running in cloud env, use proper DB like PostgreSQL
- Engine: the environment to run devcontainers: docker/podman for local and K8s for cloud

The whole concept is based on devcontainer standard ([container.dev](https://containers.dev/)), has support for IDE like VSCode / Jetbrain, has support for
Agentic Coding agents (e.g. claude code, opencode, codex cli, hermes agent), can be integrated with other TMUX tool like Herdr (https://herdr.dev/).

## How it works

It starts first with configuring the provider: local or k8s, e.g. `dev configure provider <provider_name>`.
After that, user can inits the workspace using the configured provider, e.g. `dev init workspace <workspace_name> --provider <provider_name>`.

- Provider: to say which environment the devcontainer should run in.
- Workspace: to host multiple devcontainers of one or multiple projects / repos. User settings will be also defined per workspace, e.g. Github PAT, OpenAI key, Ollama key, LiteLLM key etc... - these should be defined
as key-value pair in the workspace, which will then be injected as environment variables into the devcontainers. For SSH agent forwarding / GPG agent forwarding, depending on the provider, this settings can be enabled or not.
User should be able to define how these work per workspace too.

To start a new devcontainer: `dev container create <devcontainer_name>`
- a devcontainer can be created from a folder, or with no folder at all
- a folderless devcontainer keeps its work in a volume the provider owns, not on the host

To ssh into a devcontainer: `dev container ssh <devcontainer_name>`

Other related commands: `dev container start/stop/list/remove/rebuild/logs`
- start: start a stopped container
- stop: stop a running container
- list: list all containers in a workspace / all workspace
- remove: remove a container
- rebuild: rebuild the devcontainer image
- logs: show logs of the running container

To run the coding agent in a container: `dev container start-agent <devcontainer_name> --agent claude|opencode|hermes`
- start a container (if not started), run the agentic agent in that container. user can also specific which agent to use
- it requires that the agent should be already pre-installed in the container. If not, it should prompt user to install and rebuild it
