# Idle Stop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A container nobody has been connected to for 30 minutes stops itself, through a watchdog `dev` starts inside it, with nothing installed on the host.

**Architecture:** A POSIX shell watchdog (`internal/idle/watchdog.sh`, embedded) counts sessions from `/proc` (processes with `ppid 0` other than PID 1) and, after 30 idle minutes, writes a marker and signals PID 1 to stop the container. `idle.Ensure` copies it in through `Provider.Exec`, starts it once (pidfile), and reports any marker left by a previous stop. `internal/cli` calls `Ensure` after every `Up`/`Rebuild` and in a repair pass at the end of each run that touched the database, records `idle-stop` in the audit log, and never fails a command because of it.

**Tech Stack:** Go, POSIX sh (busybox-compatible), SQLite migrations, the devcontainer CLI through the existing local provider.

**Spec:** `docs/specs/2026-10-19-idle-stop-design.md`

## Global Constraints

- Threshold `30m`, watchdog tick `60s`, grace after `TERM` `10s`. Hidden env overrides for smoke only: `DEV_IDLE_AFTER`, `DEV_IDLE_TICK` (Go durations), read by `internal/cli`, documented nowhere but the smoke test.
- Nothing on the host: no unit, plist, daemon, or file outside the state directory.
- Nothing inside the container decides from what the agent can fake: sessions come from `/proc/*/stat` only.
- k8s gets no watchdog (experimental provider; a dead PID 1 restarts the pod).
- Idle stop never fails a `dev` command: every error is a warning on stderr.
- `--no-idle-stop` on `container create` only, fixed at create; migration default `1` for existing rows.
- Shell probes per AGENTS.md: never `test -w`; probe writability with `( : >> FILE )`.
- Unit tests touch no engine and no network; external tools are stub executables on a temp `PATH`.
- Conventional Commit subjects, no `Co-Authored-By: Claude` trailer. `make lint && make test` before every commit.
- If `git commit` fails with `Read-only file system`, leave the work uncommitted and say so.

## Spec amendment (folded into Task 7)

PID 1 inside its own namespace receives only signals it has a handler for — `KILL` included. The devcontainer CLI's default start command traps `TERM` (`trap "exit 0" 15`), so `TERM` stops the container; a project command with no handler would not. The watchdog therefore sends `TERM` to PID 1, waits the grace period, and if PID 1 is still there kills every other process with `kill -KILL -1`, leaving the container running with only its init. The marker records which happened: `stopped` or `reaped`. Task 7 writes this into the spec, together with: the repair pass runs only when the command opened the database; and the sentence "a running one is stopped" under Opting out is removed (the flag is create-only, so there is never a running watchdog to stop).

## Review Focus

1. **A project whose PID 1 has no `TERM` handler** — the container must not be left half-stopped with a watchdog looping; expect the reap fallback, marker `reaped`, watchdog exits. Test in Task 1 (`TestWatchdogReapsWhenInitSurvives`).
2. **A non-root remote user with no sudo** — `dev` must warn once and carry on, never fail the start. Test in Task 2 (`TestEnsureUnavailableWithoutRoot`) and Task 4 (`TestStartWarnsWhenIdleStopUnavailable`).
3. **A second `dev` command while the watchdog runs** — must not start a second watchdog, even when the pidfile is owned by root and the caller is not (so `kill -0` would fail with EPERM). Test in Task 2 (`TestEnsureLeavesARunningWatchdog`).
4. **A stale pidfile after the container restarted** (PID reused by an unrelated process) — must start a fresh watchdog. Test in Task 2 (`TestEnsureReplacesAStalePidfile`).
5. **The repair pass on a slow or wedged engine** — a plain `dev container list` must not hang; bounded at 10 s total, errors as warnings. Test in Task 5 (`TestRepairIsBoundedByItsTimeout`).

- [ ] **Step 3: Write `watchdog.sh` and `idle.go`**

`idle.go`: package doc ("Package idle stops a container nobody is connected to, from a watchdog that runs inside it."), `//go:embed watchdog.sh` into `Script`, the two constants. `watchdog.sh` is `#!/bin/sh`, `set -u`, POSIX only (it runs under busybox). The session count is the one piece the tests do not determine on their own:

```sh
sessions() {
	n=0
	for s in "$PROC"/[0-9]*/stat; do
		read -r line < "$s" 2>/dev/null || continue
		pid=${line%% *}
		set -- ${line##*) }
		[ "$1" = Z ] && continue
		[ "$2" = 0 ] && [ "$pid" != 1 ] && n=$((n + 1))
	done
	echo "$n"
}
```

The `run` loop: write `$$` to `DIR/pid`; `idle=0`; each tick, reset `idle` to 0 if `sessions` > 0, else add TICK; at `idle >= AFTER` write the marker `stopped`, `$KILL -TERM 1`, sleep GRACE, and if `$PROC/1` still exists rewrite the marker as `reaped` and `$KILL -KILL -1`; then exit 0. One comment, above the reap: PID 1 in its own namespace ignores every signal it has no handler for, `KILL` included.

### Task 2: `idle.Ensure` — copy in, start once, report the marker

**Files:**
- Create: `internal/idle/ensure.go`
- Test: `internal/idle/ensure_test.go`

**Interfaces:**
- Consumes: `idle.Script`, `provider.Provider.Exec`, `dcgen.StateDir` (`/var/dev-state`).
- Produces:

```go
type State string
const (
	Started     State = "started"
	Running     State = "running"
	Unavailable State = "unavailable" // not root and no passwordless sudo
)
type Stop struct {
	Outcome string        // "stopped" or "reaped"
	At      time.Time
	Idle    time.Duration
}
type Options struct{ After, Tick time.Duration } // zero means the defaults
func Ensure(ctx context.Context, p provider.Provider, c model.Container, o Options) (State, *Stop, error)
```

`Ensure` runs one `p.Exec` of `sh -c <ensureScript> dev-idle <stateDir> <afterSeconds> <tickSeconds>` with `idle.Script` on stdin and parses stdout.

**Ensure script protocol** (stdout, one item per line): optionally `marker <outcome> <unix> <idle-seconds>`, then exactly one of `started`, `running`, `unavailable`. Anything else is an error naming the container and the output.

**Ensure script behaviour:**
1. `run=` when `id -u` is `0`; `run="sudo -n"` when `sudo -n true` succeeds; otherwise print `unavailable` and exit 0. (Arguments, not env, carry every value: `sudo` strips the environment.)
2. `dir="$stateDir/idle"` when `$stateDir` exists, else `/tmp/dev-idle`; `$run mkdir -p "$dir"`.
3. If `$dir/marker` exists: print `marker ` followed by its content, then `$run rm -f "$dir/marker"`.
4. Alive check without signals (a root-owned watchdog refuses `kill -0` from a non-root caller): pid from `$dir/pid`, alive when `/proc/$pid/cmdline` is readable and contains `watchdog.sh`. Alive → print `running`, exit 0 — *after* draining stdin to `/dev/null` so the provider's stdin copy does not block.
5. Otherwise `$run sh -c 'cat > "$1"' _ "$dir/watchdog.sh"` from stdin, then start detached: `$run setsid sh "$dir/watchdog.sh" run "$dir" "$after" "$tick" </dev/null >/dev/null 2>&1 &` when `setsid` exists, else the same with `nohup`. Invoked through `sh`, so a `noexec` `/tmp` does not matter. Print `started`.
